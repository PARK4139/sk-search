# title
one-shot 실패 실행이 버전 번호를 소모해 배포 버전에 공백이 생김

# pre-condition
- 공유 `3rd_party/skim-search/versions.json` (전체 SHA ↔ 버전 배정 기록)
- 실패 후 수정 커밋으로 재실행하는 일반 흐름 (실패한 SHA는 다시 쓰이지 않음)

# steps
근거: 사용자 요청 (2026-10-02): 실패한 one-shot 실행도 버전을 하나씩 소모하는 문제 / rules/one-shot.md#버전-관리
1. 변경을 만들고 `scripts\one-shot.cmd --bump patch` 실행 → CI 실패
2. 수정 커밋 후 다시 실행 → 성공·push
3. `versions.json`과 `3rd_party/skim-search/{SHA}/` 게시 여부 비교

# actual result
- 버전은 commit 단계에서 배정되어 즉시 `versions.json`에 영구 기록된다. 이후 CI·CD·security·push가 실패해도 기록은 남고, 다음 SHA는 그다음 번호를 받는다.
- 2026-10-01~02 기록: 0.1.1, 0.2.0, 0.2.1, 0.2.2, 0.2.3 은 CI 실패로 게시되지 않음. 0.3.0 은 CD 게시 후 push 단계에서 차단(security_policy 오탐)되어 원격에 없음. 실제 push된 버전: 0.2.4 → 0.4.0 → 0.5.0 → 0.6.0 → 0.6.1.
- 같은 SHA 재시도 시 같은 버전 재사용 규칙은 정상이나, 실패 후에는 보통 새 SHA로 재실행하므로 번호만 소모된다.

# expected result
- 버전 번호는 push까지 성공한 실행에만 확정된다. 실패한 실행의 배정은 확정되지 않으며, 다음 실행은 마지막 **확정** 버전을 기준으로 계산한다. 연속된 push 버전에 공백이 없다(분류 등급에 따른 정상 증가만 있음).
- 빌드 주입·CD 게시에는 여전히 배정 버전을 사용한다(실행 중에는 예약 상태). 같은 SHA 재시도는 같은 예약을 재사용한다.
- 동시 실행에서 서로 다른 SHA가 같은 확정 번호를 받지 않는다(잠금·원자적 갱신 유지). 진행 중인 예약과 충돌하면 실패로 처리하고 이유를 기록한다.
- 확정되지 않은 예약으로 게시된 패키지(예: push 차단)는 구분 가능하게 기록한다(삭제하지 않음, 덮어쓰기 금지 규칙 유지).
- 기존 `versions.json` 기록과 호환된다(이미 배정된 항목은 그대로, 새 상태 필드만 추가). `rules/one-shot.md#버전-관리`를 갱신한다.
- 검증: 임시 저장소에서 실패→새 SHA 성공 시 번호 공백 없음, push 실패 후 재시도, 같은 SHA 재사용, 동시 배정, 기존 기록 호환 테스트 PASS. 증거는 `ref/actual/logs/`.
