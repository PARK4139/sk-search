# title
one-shot keyboard alert: state the expected duration and notify when the keyboard is free again

# pre-condition
- one-shot normal run with CI UI e2e (`tests.e2e.ui`)
- Existing alert: one toast 5 s before the UI e2e (`keyboard_alert`, rules/one-shot.md#keyboard-use-alert)
- Run logs in `ref/actual/logs/one-shot/{run}/events.jsonl` contain the UI e2e `command_start` / `command_end` times

# steps
Source: user request (2026-10-02): the "about 5 minutes" estimate was not from code; add an issue for an alert that tells how long the keyboard is needed and when it is free
1. Run `scripts\one-shot.cmd --bump patch`.
2. Check the console message at the start, the alert before the UI e2e and the alert after it.

# actual result
Not implemented.
- The alert text says only "do not use keyboard/mouse until the test finishes" with no duration.
- No alert when the UI e2e ends, so the user cannot tell when the keyboard is free.
- The run does not say up front that only the UI e2e (~45 s including the 5 s lead) needs the keyboard, while the whole run takes 3–5 min. In practice the user interrupted a normal run to use the keyboard (closed/diagnostics/one-shot-failure/bc20ea4d).
- Measured keyboard windows: run `20261002-124730-b5366c23` alert 03:48:41Z → e2e 03:48:46Z–03:49:26Z; run `20261002-091449-5d3dbe35` alert 00:16:07Z → e2e 00:16:12Z–00:16:52Z (40 s each).

# expected result
- The start alert states the expected keyboard-busy duration, computed (not hardcoded) as the median UI e2e duration of recent successful runs from `events.jsonl`, with a fallback value from `configs/one-shot.json` when no history exists. The value and its source are recorded in `state.json` `keyboard_alert` and the event log.
- When the UI e2e ends (pass or fail), one more non-modal alert says the keyboard is free, recorded as a `keyboard_free` event with the actual duration.
- At the start of a run that includes the UI e2e, the console states that only the UI e2e needs the keyboard and that an alert comes right before it. Runs without the UI e2e (`--urgent-backup`, ci off) show no such message.
- Alerts still never take focus and are still shown once per run (start + end pair).
- Automated tests: duration from history (median), fallback without history, end alert after success and failure, no alert/message for urgent-backup.
