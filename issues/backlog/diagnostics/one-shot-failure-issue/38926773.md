# title
one-shot 실패 시 단일 backlog 이슈 자동 생성·갱신으로 실패 SSOT 유지

# pre-condition
- one-shot 파이프라인과 독립 단계 진입점이 있는 Git 저장소
- 임시 저장소에서 정상 실행, 단계 실패, 시간 초과, 중복 실패, 이슈 저장 실패를 재현한다.
- 실제 사용자 저장소 commit·배포·push 없이 검증한다.

# steps
근거: 사용자 요청 (2026-10-01): failure.json 없이 이슈만 실패 SSOT; 실패 시 backlog에만 작성, 해결 후 동일 파일 closed 이동
1. 설정·commit·분류·CI(빌드/테스트/검사)·CD·보안 검사 실패 및 시간 초과를 재현한다.
2. 파이프라인 중단과 backlog 이슈 자동 생성, 우선순위 목록 등록을 확인한다.
3. 동일 전체 SHA·단계·실패 항목을 다시 발생시켜 기존 활성 이슈 갱신과 중복 방지를 확인한다.
4. 중첩 호출, 동시 실패, SHA 확보 전 실패와 이슈 저장 실패를 검증한다.
5. 해결·재검증 후 같은 UUID 파일을 closed로 이동하고 활성 우선순위 행을 제거한다.

# actual result
미구현. 현재 pipeline.py는 실패 시 실행 디렉터리에 failure.json을 생성한다. 실패 해결용 이슈 자동 생성·갱신은 없다.
- 선행 기능 구현: 사용자 지시(2026-10-01)에 따라 cores/scripts/issue_ids.py의 get_issue_id()와 Git 공통 디렉터리의 issue_ids.sqlite3 한 개를 ID 배정 SSOT로 통일했다. 기존 이슈·예약은 최초 1회만 이관하며 이후 인덱스·트랜잭션으로 배정한다. 자동 실패 이슈 생성 구현 시 이 API를 사용한다. 별도 clone 간 중복은 병합 전 확인한다.
- ID 검증 7개 PASS: 기존 이슈·예약 충돌 재생성, 동일 후보 동시 경합, 별도 프로세스 32개 및 재시작, 기존 중복 감지, 로그 실패 시 예약 유지, 이전 예약 이관·재검색 없음, 단일 DB·속도 측정. 증거: ref/actual/logs/issue-id-tests.log. 200회 API 호출의 p50 5883.4us, p95 6890.0us, 최대 151477.8us (영구 반영·로그 포함, Python 시작 및 최초 초기화 제외). 증거: ref/actual/logs/issue-id-bench.json. 이 결과는 실패 이슈 자동 생성 기능의 완료를 뜻하지 않는다.
- 검증 도구 발생·조치: SQLite 테스트 연결이 닫히지 않아 임시 DB 정리가 WinError 32로 1회 실패했다. 원인은 sqlite3 연결 context manager가 commit/rollback만 하고 close하지 않는다는 점이다. contextlib.closing으로 명시적 종료 후 전체 7개 재검증 PASS. 재발 방지: 테스트에서도 DB 연결 수명을 명시한다.

# expected result
- 실패 시 후속 단계를 중단하고 비정상 종료한다. failure.json 등 별도의 실패 요약·상태 산출물을 생성하지 않으며 실패 사실·판단·조치의 SSOT는 이슈 하나다. 기존 원본 실행 로그는 검증 증거로 보관하고 이슈에서 연결한다.
- 최초 실패는 issues/backlog/diagnostics/one-shot-failure/{uuid:8}.md에 기존 템플릿으로 생성한다. 별도의 closed 발생 기록은 작성하지 않는다. issues/priority.md에 등록한다.
- 이슈에는 실패 단계·항목, 전체 SHA, 실행 ID·시각, 종료 코드 또는 시간 초과/실행 불가 구분, 재현 명령, 마스킹한 오류 요약, 증거 로그 경로, 원인·조치·재검증 내역을 기록한다. 아직 확인되지 않은 원인은 미확인으로 적고 SHA 미확보는 사유와 함께 명시한다.
- 같은 SHA·단계·실패 항목의 활성 backlog/working 이슈는 재발 내역을 추가한다. 중첩 pipeline/독립 단계 호출과 동시 실패에서도 중복 파일·우선순위 행 및 기존 내역 손상이 없다. closed 이슈는 재개하지 않고 재발 시 새 backlog 이슈에서 연결한다.
- 해결·재검증 후 같은 UUID 파일을 closed로 이동하고 우선순위 행을 제거한다. 실패 발생 당시에는 closed 파일을 생성하지 않는다.
- 이슈 기록의 비밀정보·개인 경로는 마스킹한다. 이슈 저장 실패 시 콘솔에 오류를 출력하고 원래 실패를 유지하여 비정상 종료하며, 이를 위한 별도 실패 산출물은 생성하지 않는다.
- 구현 시 rules/issue.md#작업-중-생긴-일에 one-shot 실패의 단일 이슈 추적 예외를 반영하고 rules/one-shot.md에서 참조한다. 자동 생성·중복 방지·중단·마스킹·저장 실패의 PASS/FAIL 검증과 실행 증거를 파일로 남긴다.
