# title
one-shot 단계 on/off 설정과 비상 백업(--urgent-backup: add·commit·push만)

# pre-condition
- one-shot 파이프라인(commit → ci → cd → security → push), `configs/one-shot.json`
- 공개 원격 저장소 (rules/security.md)

# steps
근거: 사용자 요청 (2026-10-02): `configs/one-shot.json`에서 각 단계 off 제어, 비상 백업 개념으로 add > commit > push만 수행, 이름 `--urgent-backup`, security_policy는 유지(규칙으로 고정)
1. `configs/one-shot.json`의 `"stages": {"ci", "cd", "security", "push"}`로 단계 on/off를 설정한다. commit은 항상 실행한다.
2. `scripts\one-shot.cmd --urgent-backup`은 설정과 무관하게 ci·cd·security를 끄고 commit → push만 실행한다.
3. push 직전 `security_policy` 검사는 어떤 모드·설정에서도 끌 수 없다(스위치 없음).

# actual result
미구현. 모든 단계가 항상 실행되며, push는 CD 패키지·security 결과가 있어야만 가능하다.

# expected result
- `stages` 설정으로 ci·cd·security·push를 끌 수 있다. 잘못된 키(`commit`, `policy` 등)·비불리언 값·의존 위반(cd는 ci, security는 cd 필요)은 실행 전에 실패한다.
- 꺼진 단계는 `state.json`에 `skipped`로, 이벤트에 `stage_skipped`로 기록된다. 켜진 단계의 순서·실패 전파는 그대로다.
- `--urgent-backup`: commit(add 포함) → push만. 버전 배정·빌드·패키지·gitleaks/audit 없음. push 직전 security_policy exit 0 필수, fast-forward만(force 금지), push 후 원격 HEAD 확인. 콘솔과 상태에 `urgent-backup: ci/cd/security skipped`를 남긴다.
- security_policy가 차단하면 urgent-backup에서도 push하지 않는다.
- 일반 실행(기본 설정)의 동작·검증 결합은 변하지 않는다.
- `rules/one-shot.md`, `rules/security.md`에 단계 스위치·비상 백업·security_policy 필수 규칙을 반영한다.
- 임시 저장소·임시 bare 원격으로 urgent push 성공, urgent 정책 차단, 설정 검증, 단계 skip 기록을 테스트한다.
