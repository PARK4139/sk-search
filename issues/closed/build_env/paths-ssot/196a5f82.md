# title
Language-neutral path SSOT (cores/common/paths.ini) with fastest Rust and Python constants

# pre-condition
- Prerequisite: build_env/repo-layout/d9be0edb (moved to the target layout)

# steps
Source: user request (2026-10-01): manage language-independent shared items (paths etc.) as an SSOT in `cores/common/`, convert them to the fastest callable form for both Rust and Python, no separate `paths.py` in Python. Measurements: `ref/actual/logs/paths-bench.log`
1. Create `cores/common/paths.ini`. Format: `KEY=path relative to the root`, `/` separators, no substitution, `#` comments.
2. Rust: `cores/rust/common/build.rs` generates `pub const` items in `OUT_DIR/paths.rs` from `paths.ini` (`rerun-if-changed`), exposed as `common::paths`.
3. Python: a generator writes string constants into the generated region of `cores/python/src/skim_search/__init__.py`. `ROOT` is computed once at a fixed depth; values are built by string concatenation `ROOT + "/..."`. No `pathlib` / `os.path` import. Usage: `from skim_search import KEY`.
4. Replace scattered path arithmetic (`parents[N]`, `HERE`, the config's `third_party`, `CORES / "target"`, …) with SSOT constants. Environment overrides such as `CARGO_TARGET_DIR` are checked once by the consumer.
5. Run the generator in `scripts\test.cmd` and as the first one-shot CI step.

# expected result
- Paths are defined only in `cores/common/paths.ini`. No repository structure path strings or `parents[N]` arithmetic remain in Rust/Python code.
- Rust: path constants are compile-time constants (`const &str`) with no file reads at runtime. A change to `paths.ini` is picked up by the next `cargo build` automatically.
- Python: no separate path module. No imports outside the generated region of `__init__.py`; the extra package-load cost of the paths is at most 50 µs over the baseline (measured and recorded).
- A test confirming Rust and Python resolve each key to the same path passes.
