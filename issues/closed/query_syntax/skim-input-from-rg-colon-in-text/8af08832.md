# title
skim_input_from_rg drops a line as malformed when its content contains ':'

# pre-condition
- `cores/app/src/query_syntax/mod.rs` `skim_input_from_rg` (implemented by another contributor, used by content-filter-path-contamination)

# steps
Source: handover §11 (rg output path/line/column/text) / Origin: first batch incl. search_engine/auto-search-on-input (code review)
1. Input the rg output `C:\a.ts:12:3:foo: bar`

# actual result
- Occurred: `rsplitn(4, ':')` splits from the right → cut at the ':' inside the content, column/line parsing fails → treated as malformed.
- Cause: the content (text) is the last field but the split starts from the right.
- Action: the app's search path does not use this function (the engine uses rg `--null` + `ripgrep::parse_line`, and sk gets `id\tcontent`). The function is used only in tests.
- Result: unresolved at first → fixed by `query_syntax/skim-input-from-rg-colon-fix`, which splits from the left; tests pass (closed).

# expected result
- The rg output conversion splits path/line/column/text correctly even when the content contains ':'.
