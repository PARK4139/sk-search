# title
Editing scripts with sed/awk damages `\` in Windows paths

# pre-condition
- Editing a PowerShell script with bash `sed` / `awk` substitution
- Replacement strings contain Windows paths (`$root\cores`, `target\debug\...`)

# steps
Source: AGENTS.md 8 (minimal, exact changes) / Origin: search_engine/rg-sk-executable-detection/5ea570b8
1. Edit the e2e script with `sed -i 's|...|...$root\\cores...|'`
2. Retry the same with `awk`

# actual result
- Occurred: `\c` became a control character (`^O`), and `\d`, `\s` etc. disappeared, giving `"$rootcores"`, `targetdebugskim-search.exe`.
  - The first rerun happened to have a cwd inside the workspace, so `cargo build` succeeded and hid the defect.
- Cause: backslash escape handling in sed/awk replacement strings.
- Action (2026-10-01): fixed the lines with the Read/Edit tools. Verified by rerunning from an unrelated cwd (`%TEMP%`).
- Prevention: edits containing Windows paths use the Edit tool instead of sed/awk. Scripts are verified from a cwd outside the repository.
- Result: PASS — from `%TEMP%`, `BUILD_FAILED` before the fix, case A/B/C exit 0 after.

# expected result
- Path strings in the edited script match the intent.
- The script works from a cwd outside the repository.
