# title
e2e 스크립트가 System Default 검증 중 사용자의 VS Code 창을 닫음

# pre-condition
- 사용자 PC에서 VS Code(<user workspace> 작업 공간) 실행 중, `.txt` 기본 앱 = VS Code
- `cores/tests/scripts/e2e_ui.ps1` run 3 (editor=system)

# steps
근거: rules/environment.md#스크립트-작성-주의, AGENTS.md 9 / 발생: search_engine/auto-search-on-input (1차 묶음 e2e)
1. skim-search에서 `open-test.txt` 선택 후 `[파일 열기]` (System Default = ShellExecute open)
2. 스크립트가 제목에 `open-test` 가 포함된 창의 프로세스를 찾아 `CloseMainWindow()` 호출

# actual result
- 발생: `.txt`가 사용자의 기존 VS Code 창에 탭으로 열림 → 스크립트가 그 창(`open-test.txt - <user workspace> - Visual Studio Code`)을 테스트 창으로 오인해 닫기 요청 → VS Code 프로세스 0개 확인.
- 원인: "제목에 파일명이 포함된 창 = 테스트가 연 창"이라는 잘못된 가정. 기본 앱이 이미 실행 중인 사용자 앱이면 기존 창을 재사용한다.
- 조치 (2026-10-01): 스크립트에서 창 닫기 제거. System Default 검증은 `-SystemOpen` 옵션일 때만 실행하고 열린 창은 그대로 둔다. 사용자에게 즉시 보고.
- 결과: 재발 방지 조치 PASS (이후 e2e 4회 실행에서 사용자 창 닫기 없음). 사용자 데이터 영향은 사용자 확인 대기 — 사용자에게 보고 완료, 2026-10-01 20:1x 기준 VS Code 미실행 (VS Code hot exit 기본값이면 재실행 시 미저장 내용 복원). 개발 측 해결 작업 없음.
- 재발 방지: 테스트 스크립트는 자신이 시작한 프로세스·창(PID 또는 실행 전후 HWND 비교로 식별)만 닫는다. 사용자 앱으로 열리는 동작은 opt-in.

# expected result
- e2e 스크립트는 사용자가 실행 중인 앱의 창·프로세스를 닫거나 종료하지 않는다.
