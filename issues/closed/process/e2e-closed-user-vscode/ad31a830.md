# title
The e2e script closed the user's VS Code window during the System Default check

# pre-condition
- VS Code (workspace <user workspace>) running on the user's PC, default app for `.txt` = VS Code
- `cores/tests/scripts/e2e_ui.ps1` run 3 (editor=system)

# steps
Source: rules/environment.md#script-writing-cautions, AGENTS.md 9 / Origin: search_engine/auto-search-on-input (first batch e2e)
1. In skim-search select `open-test.txt`, then `[파일 열기]` (System Default = ShellExecute open)
2. The script finds the process of a window whose title contains `open-test` and calls `CloseMainWindow()`

# actual result
- Occurred: the `.txt` opened as a tab in the user's existing VS Code window → the script mistook that window (`open-test.txt - <user workspace> - Visual Studio Code`) for the test window and requested it to close → 0 VS Code processes confirmed.
- Cause: the wrong assumption "a window whose title contains the file name = the window the test opened". When the default app is a user app that is already running, the existing window is reused.
- Action (2026-10-01): removed window closing from the script. The System Default check runs only with the `-SystemOpen` option and leaves the opened window alone. Reported to the user immediately.
- Result: prevention PASS (no user windows closed in 4 later e2e runs). Impact on user data awaits user confirmation — reported to the user; as of 2026-10-01 20:1x VS Code is not running (with the VS Code default hot exit, unsaved content is restored on restart). No development-side fix work.
- Prevention: test scripts close only processes/windows they started (identified by PID or by HWND before/after comparison). Opening in user apps is opt-in.

# expected result
- e2e scripts never close or kill windows or processes of apps the user is running.
