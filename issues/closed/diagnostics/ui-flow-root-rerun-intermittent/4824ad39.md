# actual result
- 발생: 최초 cargo test에서 ui_flow.rs:387 검증 실패. 그룹은 sample file.md, install.md였고 login-guide.md가 누락됐다. 증거: ref/actual/logs/cargo-test.log. 후속 검증에서 추적 가능한 검색 데이터의 공통 원본을 코드·임시 파일 생성 대신 cores/tests/fixtures/sample/tree/로 관리하기로 해 fixture 이관함.
- 원인: 미확인. ID 생성 변경은 Python 및 이슈 문서에 한정된다.
- 조치: 공통 fixture를 `cores/tests/fixtures/sample/tree/`로 추가하고 검색 테스트의 데이터 출처로 연결했다. ui_flow 단독 재실행 PASS 증거: ref/actual/logs/issue-id-ui-flow-retry.log.
- 원인 (2026-10-02 확인): 엔진·완료 이벤트 문제가 아님. 실패 시 앱 로그 `generation=9 completed_ms=78.5 rg_lines=2 result_count=2` — rg 자체가 2개만 반환. 앞 단계 "edit + Ctrl+S saves"/"external change blocks save"가 **프리뷰 중인 파일**을 수정(`changed outside`로 덮어씀)하는데, 첫 쿼리 `login`의 첫 결과(=프리뷰 파일)는 rg 병렬 출력 순서에 따라 달라짐. 그 파일이 `docs/login-guide.md`일 때만 `TODO`가 사라져 재검색에서 누락.
- 함께 발견: "wait code/explorer args" 단계가 가짜 `echo %* > file`의 truncate 직후(빈 파일)를 읽어 빈 메시지로 실패 (one-shot run 20261002-011855-e4b1fc1f, ui_flow.rs:266).
- 조치: (1) args 대기 단계는 줄바꿈까지 기록된 뒤에만 검증. (2) 재검색 검증 기대값을 고정 파일명 대신 그 시점 디스크의 `docs/*.md` 중 `TODO` 포함 파일로 계산, `README.md` 미포함 유지.
- 결과: PASS — 수정 전 8회 중 2회·15회 중 1회 실패 → 수정 후 `cargo test -p tests --test ui_flow` 30/30 PASS, clippy -D warnings PASS. 증거: `ref/actual/logs/ui-flow-args-race.log`, `ref/actual/logs/skim-search.log`(generation=9 rg_lines=2).
