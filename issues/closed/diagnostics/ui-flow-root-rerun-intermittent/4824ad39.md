# actual result
- Occurred: the first cargo test failed the check at ui_flow.rs:387. Groups were sample file.md and install.md; login-guide.md was missing. Evidence: ref/actual/logs/cargo-test.log. For traceable search data in later verification, the common source moved from generated code/temp files to the fixture cores/tests/fixtures/sample/tree/.
- Cause: unconfirmed at first. The ID allocation change touched only Python and issue documents.
- Action: added the common fixture `cores/tests/fixtures/sample/tree/` as the data source of the search tests. Standalone ui_flow rerun PASS evidence: ref/actual/logs/issue-id-ui-flow-retry.log.
- Cause (confirmed 2026-10-02): not an engine or completion event problem. The app log at failure shows `generation=9 completed_ms=78.5 rg_lines=2 result_count=2` — rg itself returned only 2. The earlier steps "edit + Ctrl+S saves" / "external change blocks save" modify **the previewed file** (overwritten with `changed outside`), and the first result of the first query `login` (= the previewed file) depends on rg's parallel output order. Only when that file is `docs/login-guide.md` does `TODO` disappear, so it is missing from the rerun.
- Found together: the "wait code/explorer args" steps read the fake `echo %* > file` right after truncation (empty file) and failed with an empty message (one-shot run 20261002-011855-e4b1fc1f, ui_flow.rs:266).
- Action: (1) the args wait steps check only after the line including the newline is written. (2) the rerun expectation is computed from the `docs/*.md` files on disk containing `TODO` at that time instead of a fixed file name; `README.md` stays excluded.
- Result: PASS — before the fix 2 of 8 and 1 of 15 runs failed → after the fix `cargo test -p tests --test ui_flow` 30/30 PASS, clippy -D warnings PASS. Evidence: `ref/actual/logs/ui-flow-args-race.log`, `ref/actual/logs/skim-search.log` (generation=9 rg_lines=2).
- Expected result changed: "contains login-guide.md" was a data-dependent condition depending on what earlier steps modified, so it became "equals the matching files of the new root on disk" (keeping the original intent that the rerun uses the new root).

# expected result
After a search root change completes, results are based on the new root, equal the `docs/*.md` files matching the query on disk at that time, and do not include README.md. Runtime logs confirm the completion event and the results belong to the same search run.
