# actual result
- Occurred: CI stage `FAIL: release executable SHA/version mismatch` — `skim-search.exe --version` = `skim-search 0.1.0 unassigned` (expected `0.1.1 <SHA>`). Push not called, remote unchanged.
- Evidence: the pipeline release build finished at 12:49:08Z (app recompiled with env). `target/release/skim-search.exe` modified at 12:50:34Z = modification time of the other contributor's `ref/actual/logs/cargo-build.log` (build without env → build.rs default `unassigned`). e2e and benchmarks in between PASS.
- Cause: the pipeline and other work shared the same `CARGO_TARGET_DIR`. The check itself blocked as intended.
- Action: CI uses `CARGO_TARGET_DIR=cores/target/one-shot` and the default artifact path moved with it. The EXE paths in `skim_tests.common` follow `CARGO_TARGET_DIR` → e2e checks the exe built by the pipeline.
- Result: PASS — `test_pipeline` 18/18. The real one-shot rerun is recorded separately.
- Additional risk: the commit stage runs `git add --all`, so another contributor's in-progress files can enter the push range → the working tree must have no other contributors' changes before a run.

# expected result
- CI, checks and deployment run on the exe built by the pipeline regardless of concurrent builds.
