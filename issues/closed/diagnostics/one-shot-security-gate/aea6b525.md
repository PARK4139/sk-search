# expected result
- The push stage proceeds only with a security result bound to the same SHA and package checksum. The result is invalidated if sources, target SHA or package change after the check.
- Secret checks cover the commit history new to the remote, including secrets deleted later but still in earlier commits. Without a remote base the check does not pass.
- Detected secrets, vulnerabilities at or above the configured severity, checks not run, tool failures, timeouts and missing vulnerability data return non-zero exit codes and no push is called.
- Exceptions state ID, reason, scope and expiry and are recorded in the result. Scope and unsupported items are reported; passing is never presented as "no security risk at all".
- UTF-8 logs and structured reports are saved in `ref/actual/logs/one-shot/`, including full SHA, commit range, package checksum, tool / version / data time, policy, and detection location / severity / block result. No raw secrets or credentials are recorded.
- Automated verification that no failure path calls push. The success-path push wiring is verified with temporary local remotes or mocks. No push to the real origin.
- On timeout the started child processes and temporary files are cleaned up. Installation, running, policy and result checking are documented.
- For each blocking item of rules/security.md (SEC-SECRET, SEC-LOCALPATH, SEC-EMAIL, SEC-PATH, SEC-VULN, SEC-TOOL) a fixture test blocks on detection, and allow-list cases (noreply e-mail, `%USERPROFILE%` notation) pass.
- The checked range is limited to the push range (`<remote>/<branch>..<ref>`). Contamination only in local refs (stash etc.) does not block (false positive test).
- The same check can run standalone before a manual push outside the pipeline (independent `security` stage entry point).
