# title
Screen evidence captures include other windows (user screen content)

# pre-condition
- First version of `cores/tests/scripts/run_capture.ps1` (uses `Graphics.CopyFromScreen`)
- The user is using another window (overlapping the skim-search window)

# steps
Source: rules/environment.md#evidence-paths, AGENTS.md 9 / Origin: view/main-ui-components-missing/521ce549
1. Launch and capture skim-search with `run_capture.ps1`

# actual result
- Occurred: `SetForegroundWindow` was refused so the user's window stayed in front → `CopyFromScreen` copied the screen area as is and the user's editor content was saved into the evidence file.
- Earlier defects of the same script, recorded together:
  - `Process.MainWindowHandle` pointed at the debug build console window → 16x16 capture, WM_CLOSE went to the console, exit code `0xC000013A` (forced termination)
  - `FindWindow($null, ...)`: PowerShell passes `$null` as `""` → window not found
  - Window minimized at start → 160x28 capture
- Action (2026-10-01):
  - Overwrote the contaminated evidence file immediately
  - Find the window with `FindWindow([NullString]::Value, "skim-search")`, `ShowWindow(SW_RESTORE)`
  - Capture only the target window content with `PrintWindow(hwnd, PW_RENDERFULLCONTENT)`
  - Close by sending WM_CLOSE to the target window
- Result: PASS — 1168x807 capture of the skim-search window only, exit code 0, log `[app] exit ok`
  - Evidence: `ref/actual/screenshot/frames/main-ui-components-missing_100.png`, `ref/actual/logs/skim-search.log`

# expected result
- Capture files contain only the skim-search window content (even with overlapping windows).
- The app exits normally after the capture (exit code 0).
- Evidence: capture PNG, `ref/actual/logs/skim-search.log`
